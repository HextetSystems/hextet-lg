# Next-hop reverse DNS

`ptr_enrichment` is optional and disabled by default. Enable it in the YAML and restart the service. The example configuration documents all settings. Defaults are a two-second timeout, four workers, 64 uncached addresses per visible page, 10,000 cache entries, a 720-hour positive TTL and a 24-hour negative TTL. The cache is in memory only, is lost on restart, and requires no writable filesystem.

For table pages, the primary address is the existing operational `NextHop()`: true next hop when present and not `???`, otherwise exit next hop. Expanded details also display both fields; each eligible address gets its own tooltip. Invalid displayed values are not resolved; when the operational value is invalid, a valid displayed exit address receives scheduling priority while the displayed operational value is preserved. Primary addresses are scheduled first, then the two detail fields, in page order, deduplicated. Only routes that survived visibility filtering and appear on that page are considered. Text and plain views do not schedule PTR lookups. The route prefix does not determine the next-hop address family.

Literal IPv4 and IPv6 addresses are accepted; IPv4-mapped IPv6 is normalized to IPv4. Private IPv4, ULA, documentation and globally routable addresses are eligible. Unspecified, multicast, loopback, link-local and zoned addresses are excluded. Link-local scope is never guessed. Hostnames, ports and prefixes are rejected.

The system resolver performs PTR lookups asynchronously with a timeout. A valid ASCII hostname has ordinary DNS labels; the root dot is removed and case preserved. Up to 64 records are accepted, with the case-insensitive lexicographically first valid hostname selected (case-sensitive tie-break). No forward confirmation is performed. Empty answers and DNS not-found answers are negatively cached; malformed records, timeouts, cancellation and other resolver errors instead receive a ten-second retry delay. During an outage, addresses remain visible without tooltips.

The cache-only `/ptr-status?ip=...` endpoint accepts at most 256 comma-separated literal addresses and never starts DNS work. It shares the normal HTTP request limits and rate limiter. The existing bounded ASN UI update cycle also reads PTR status; navigation invalidates stale replies. DNS records and addresses sent to a resolver may disclose network topology to that resolver; use a trusted DNS service and consider this before enabling enrichment. Hostnames are escaped as HTML and are not included in logs or metric labels.

For an expected deployment of 500–1,000 distinct next hops, the measured mock-backed cost for a 100-route page was approximately 10.0 ms disabled, 17.6 ms with a cold cache, and 12.5 ms with a warm cache. These variable measurements represent an accepted engineering tradeoff; DNS resolution remains asynchronous.
